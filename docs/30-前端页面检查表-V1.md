# 前端页面检查表 V1

版本：1.0 · 日期：2026-11-16 · 适用项目：新裴贸易业务管理系统

## 1. 使用规则

这是一份待执行的检查规范，不是已通过的验收报告。历史截图和测试结果只能作线索，不能直接给当前版本打勾。

三种结论分别记录：**页面可打开、检查项通过、页面验收通过**。不得互相替代。

- 检查状态只有：**通过、失败、未测、不适用**。未测注明阻碍；不适用注明理由；不能空着。
- “通过”必须同时满足操作步骤、预期结果和证据要求。存在例外时按例外记录，不笼统写“正常”。
- 每个页面逐项套用下面的检查表。相同组件可以复用证据，但必须说明页面、控件、状态与视口的映射；同一组件名称不证明其在不同父布局中表现相同。
- 三档 CSS 视口：1440×900、1280×720、390×844；记录实际 `innerWidth/innerHeight`。浏览器缩放默认为100%，设备像素与CSS像素分开记录。
- 固定待验收版本：记录URL、时间、用户角色、语言/时区、部署标识（可获得时）和现有测试数据。源码版本不自动代表容器版本。检查中若重新部署，标出受影响的过期证据。
- 全程以 ego-lite 前端操作为事实依据。允许只读DOM测量；禁止直接调用业务API、用页面脚本执行fetch提交、改React状态、写数据库或后台造数来冒充前端流程。
- 操作权限沿用当前会话明确授权。默认只读；创建资料、上传、保存、删除、审批、发货、收付款、库存调整、权限修改分别界定。不能把“允许创建演示商品”扩展成“允许所有写操作”。已获得授权的同类操作不重复请示。
- 检查用户可见过程时，先确认用户正在看的任务空间，再继续演示；不能把另一个后台标签页的操作当作用户已经看到。

## 2. 执行顺序与范围

1. 从当前菜单和真实路由建立页面清单，展开分组，补充详情、二级页签、弹窗与抽屉入口。历史42个入口仅作起点，不当作永久全量。
2. 记录每页的主要用户任务、可见操作、已知数据状态和操作权限。
3. 先检查默认页面和滚动，再检查筛选/浮层，然后检查表单、详情及已授权业务闭环。
4. 在三档视口分别检查实际布局与可达性。不要只缩放截图，也不要通过隐藏溢出遮住问题。
5. 发现问题后重复同一安全路径核实；给出步骤、实际与预期、影响、截图和必要尺寸。疑似根因与确认事实分开。
6. 所有未测项和失败项进入同一覆盖矩阵，再形成统一问题清单。问题按共同原因归并，但保留每个受影响页面的证据。

### 状态覆盖要求

对每个实际存在的控件记录：默认、聚焦、输入后、展开/选中、错误、禁用、加载、空结果。没有该状态才可标“不适用”；数据条件不足应标“未测”。

每页三档视口都需覆盖默认布局、主要操作组、实际滚动和有代表性的浮层/表单。完整业务闭环可以先在一档执行；若声称多设备业务均通过，则必须在相应设备重新执行，不能从桌面推断手机。

## 3. 逐项检查表

下表为检查项目定义。实际执行结果填入第5节的逐项台账。

### A. 页面结构与用户理解

| 编号 | 操作/观察 | 通过条件 |
| --- | --- | --- |
| A01 | 从菜单进入页面、返回列表、刷新详情 | 标题、选中菜单、URL、内容对应；没有跳错页、空白页或无故丢失当前对象 |
| A02 | 阅读标题、字段、按钮、说明 | 使用一致业务术语；无无意义重复标题、未翻译状态码；内部ID不替代姓名/编号。确有审计用途的ID可保留并说明用途 |
| A03 | 区分列表统计与单条详情 | 统计注明范围、单位；全库数、筛选结果数、当前对象数不混用，例如有图商品件数与图片张数 |
| A04 | 找到页面主操作 | 新增/生成入口明确；筛选与主操作有合理分组；没有按钮意外落入某个字段列下方 |
| A05 | 比较有数据、未建档、筛选无结果、加载失败 | 文案准确区分原因；分别提供创建、清空条件、重试等适当入口，不一律显示暂无数据 |
| A06 | 查看已完成、已关闭、停用对象 | 主标题和明细标题与状态一致；仍能执行被允许的只读查看；无需绕到别的模块找结果 |

### B. 布局和控件内部视觉

| 编号 | 操作/观察 | 通过条件 |
| --- | --- | --- |
| B01 | 对照同一工具栏的输入、选择、日期、按钮 | 同类控件高度与上下边缘一致；差异有明确设计目的；不能只检查外框而忽略内容 |
| B02 | 查看普通、聚焦、填写后的控件内容 | 文字、前缀图标、后缀图标、日期分隔符垂直居中，无明显偏上/偏下 |
| B03 | 查看数字+单位、百分号、搜索前缀等组合控件 | 只有清晰完整的外框，无框套框、双重圆角或不协调的接缝；后缀不会挤压数值 |
| B04 | 检查字段宽度和按钮宽度 | 字段按内容与布局分配；按钮不被无意拉成长条，也不因等分导致文字裁切；关联字段相邻 |
| B05 | 比较标题→说明→工具栏→表格间距 | 间距有统一层级；不出现上方大片空白、下方贴在一起的失衡布局 |
| B06 | 查看帮助文字、placeholder、状态和禁用态 | 正常文字可读，禁用态单独区分。普通文字对比度以4.5:1为检查目标；记录实际颜色、背景和透明度，不凭截图猜数值 |
| B07 | 查看复选框、单选框、开关与标签 | 图标不被输入框规则放大，文字同行居中；图形尺寸与点击区域分别检查 |
| B08 | 用正常长度及较长测试文字观察字段/表格 | 名称、日期、单号、金额可辨认；金额的小数不拆开；有意省略时提供可用的完整内容查看方式 |

测量口径：同排、同规格外框的位置偏差原则上不超过1个CSS像素（考虑舍入）。字体字形存在光学差异，不用每个字的像素包围盒机械判错；以内部容器对齐和实际视觉共同判断。文案完整也不等于按钮命中区域完整。

### C. 筛选、表格与浮层

| 编号 | 操作/观察 | 通过条件 |
| --- | --- | --- |
| C01 | 输入已有记录关键词→查询→清空/重置 | 结果正确变化；清空恢复原结果；不把只填写未查询误当作查询成功 |
| C02 | 查询不存在的安全关键词 | 明确显示没有匹配结果，提供恢复入口；统计范围表达正确 |
| C03 | 打开下拉、搜索选择、选中、点击外部 | 选项可读可选；选中值保留；关联字段正确回填；没有残留空白标签或浮层遮挡 |
| C04 | 选择开始/结束日期→查询→重置 | 日期范围显示与查询一致；中文月份/星期统一；分隔符居中；重置真正清空 |
| C05 | 打开日期、选择、通知、列设置浮层 | 动画结束后浮层在可用区域内，关键选项可滚到并可点击；合理避让窗口边缘不算错误 |
| C06 | 操作分页、每页条数、排序（存在时） | 页码、总数、行顺序正确；变化后不会停在没有结果的失效页；无测试数据则记未测 |
| C07 | 横向滚到表格最后一列，纵向滚到最后一行 | 末列、行操作、分页可达；区分合理的表格局部滚动与整页被撑宽 |
| C08 | 点击不同状态记录的编号/查看入口 | 进入正确对象；已完成状态也保留允许的查看入口，不只有空操作列 |

### D. 表单完整生命周期

| 编号 | 操作/观察 | 通过条件 |
| --- | --- | --- |
| D01 | 首次打开新增/编辑 | 标题与模式正确；新增从顶部开始；默认值合理；编辑加载的是当前记录 |
| D02 | 按业务名称或编号选择关联资料 | 无需用户手填内部ID；名称、规格、单位等正确带出；不能把仅显示选择器当作回填已验证 |
| D03 | 切换关联对象、清空选择 | 旧对象的派生字段随之更新或清空；不会留下上一客户/商品的资料 |
| D04 | 在已授权范围内留空必填后触发校验 | 星号明确，字段旁错误常驻，红框及aria-invalid匹配，焦点到错误字段；toast不能作为唯一反馈 |
| D05 | 触发错误后等待toast消失、移焦、补填 | 未修正的字段仍有错误；聚焦蓝框不能覆盖错误色；补填后错误正确清除 |
| D06 | 滚动长表单和多段操作区 | 所有字段、帮助文字和每段按钮可达；固定标题/底栏不遮住最终可操作内容 |
| D07 | 填写草稿→取消→重开；编辑→取消→新增；切换记录 | 滚动位置重置符合预期；不串用上一条数据；若保留草稿需有明确设计，不暗中残留 |
| D08 | 已授权保存→成功反馈→返回列表→刷新→打开详情 | 保存内容正确且持久；记录数变化合理；不能用关闭弹窗或瞬时成功提示单独证明保存成功 |
| D09 | 查看提交中、失败后恢复（可安全复现时） | 提交中避免重复动作；失败不丢草稿、不误报成功；无法安全触发时记未测，不制造破坏性故障 |
| D10 | 点击取消、关闭、Escape并观察焦点 | 行为符合设计；退出后焦点合理返回；没有留下遮罩、锁滚动或无法操作的页面 |

## 4. 证据标准与缺陷分级

每个失败项至少包含：**当前版本/时间、角色、页面路径、视口、数据编号、前置条件、操作步骤、预期、实际、用户影响、截图、严重度、建议**。根因未经源码或运行证据确认时写“待定位/推测”，不能给出确定原因。

截图记录业务步骤：进入、打开、填写/选择、错误或展开、保存结果、刷新回读。长表单有上下段截图。无需对每次敲键截图，但不能遗漏上传、校验、关闭重开等关键状态。使用截图前必须实际查看，确认没拍到过渡态或错误页面。

| 级别 | 判定示例 |
| --- | --- |
| P1 | 核心任务无法完成、已确认数据丢失/错误提交、敏感权限边界异常；停止相关写操作，保留证据 |
| P2 | 用户任务被阻断或明显误导：必填无反馈、详情入口缺失、金额/状态冲突、关键操作裁切 |
| P3 | 可用但质量不一致：图标偏位、间距失衡、轻度文案歧义、点击区域偏小 |

本规范不是安全渗透测试规程。不得进行越权、注入、并发账务、破坏性边界等测试；功能异常不能仅凭截图推定为安全漏洞。

## 6. 通过与结束条件

- **检查项通过**：相应步骤已执行，预期满足，证据可复核。
- **修复点复验通过**：原复现路径通过，相关状态与共享影响面已按声明范围回归；不能据此宣布整页通过。
- **页面验收通过**：该页本轮约定的全部适用检查项均通过，无未测和未关闭失败项。不适用项有理由。
- **只读页面检查通过**：只读子集通过；写入生命周期必须单列未测，不能简写为页面验收通过。
- **全站验收通过**：本轮明确清单中全部页面满足页面验收条件。存在未测、失败或被排除范围时，不使用“全站全部通过”。
- 到权限、环境或数据限制时，完成能独立继续的检查，留下未测项和下一步；不能虚构测试，也不为凑通过率扩大操作权限。
- 每次报告同时给出：入口数量、实际场景数量、通过/失败/未测/不适用数量、剩余缺陷、数据变更及证据路径。重复视口与复验次数不计为新页面。

## 7. V1维护方式

每次用户或后续使用发现漏检，判断是已有项目未执行，还是规范缺项。前者纠正执行记录，后者补充可复现的检查项并升级版本。不要只把新问题加入历史缺陷列表，而不改变下轮检查方法。
