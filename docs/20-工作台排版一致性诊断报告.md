# 工作台排版一致性诊断报告

> 阶段：只诊断，未改任何样式、未提交代码。  
> 视口：1440 × 813（DPR 1），Chrome headless，登录 `admin`。  
> 方法：`getBoundingClientRect()` + `getComputedStyle()` + 文本 `Range` 实测；像素值保留 1 位小数，文本行取字形盒左边。  
> 证据目录：`.screenshots/layout-consistency/`

---

## 0. 结论摘要

1. **红色竖线是截图标注，不是页面元素**。像素取样 `#F54A45`、4 CSS px、两端圆头，代码与运行时均无此颜色/边框；它标出的是「页面标题、统计卡片、内容卡片左边缘不在一条线上」。本报告不再把它当 bug。
2. 三层左边缘实测落在 **264 / 268 / 280 / 291 / 307** 五条线上（工作台），列表页是 **264 / 281 / 308 / 321** 四条线。根因不是某个像素，而是**横向内边距在 5 个层级各加了一次**，且同一个 `.workspace-panel` 在首页被拆成两套 padding。
3. 工作台统计条 4 格各 118px、间距 57.6px，共 649px；容器 1152px，**右侧空 503px**。列表页同职责统计条是 4 等分铺满，两套统计卡并存。
4. 同页同组件 `.workspace-panel.dashboard-panel`：快捷入口保留 `padding:16px`，其余四张被覆盖为 `padding:16px 0`，导致标题图标 280 与 264 并存。
5. 页面级纵向节奏三套：工作台 12px、masterdata 14px、审计页 16px；规范要求 16px。
6. 空状态至少 **4 个家族**：`.dashboard-empty`（虚线、左对齐、整行按钮）、AntD `ant-empty`（插图）、审计页纯文字、详情页 `.module-state`（居中、220px 虚线）。待办列表页又用 AntD 图标空态，与工作台「暂无待办」同文案不同形态。
7. 快捷入口「还没有快捷入口」下方直接渲染 4 个推荐入口，文案与画面矛盾；「新增日程 / 发布公告」夹在快捷入口与看板之间，归属不清；两列卡片底边实测 696 / 700，且 `align-items:start` + `grid-row:2 / span 2` 会让内容变高时底部空档扩大。

## 2. 横向间距来源链路（为什么会差）

同一条「内容左边缘」，实际被 5 个层级分别加了一次：

| 层级 | 规则 | 文件:行 | 实际值 |
|---|---|---|---:|
| 页面容器 | `body .react-workspace { padding: 20px 24px 32px }` | `design-system-apply.css:28` | 24 |
| 统计条 | `.react-shell-home .metric-strip { padding:15px 4px 16px }` | `dashboard.css:25` | +4 |
| 统计格 | `.react-shell-home .metric-strip .metric-cell { padding:0 }` | `dashboard.css:73-77` | +0 |
| 统计格（列表页） | `.summary-cell { padding:14px 16px }` | `shared-primitives.css:123-127` | +16 |
| 卡片 | `body .workspace-panel { padding: var(--ui-space-4) }` | `design-system-apply.css:200-204` | +16 |
| 卡片（首页四张） | `padding: var(--ui-space-4) 0` | `design-system-apply.css:1060-1066` | +0 |
| 空状态 | `.dashboard-empty { padding: 0 12px }` → 契约层 `padding: 12px` | `dashboard-todo.css:182-191`、`design-system-apply.css:1253-1261` | +12 |
| 表格单元 | AntD 默认单元格 padding | 组件库 | +16 |

**其中最关键的一条**：`design-system-apply.css:1060-1066` 只列了 primary / schedule / reminders / announcements 四张卡，**漏掉了 `.dashboard-shortcut-panel`**。同一个 `.workspace-panel.dashboard-panel`，快捷入口走 16px，其余四张走 0。这是 264 / 280 分裂的直接原因。

统计条还有一条**契约规则被更高优先级覆盖**的问题：契约层 `.metric-cell { padding: 8px 12px }`（`design-system-apply.css:991`）被 `dashboard.css:73-77` 的 `.react-shell-home .metric-strip .metric-cell`（3 个类）压过，实际 padding 为 0。所以契约层「12px 内缩」从未生效，实际是 4px。

### 2.1 两列间距与页边距是否同源

- 看板外框：264 ~ 1416，与内容区一致，外侧 margin = 0。
- 列间距：`gap: 0 var(--ui-space-6)` = **24px**（`design-system-apply.css:1041`）；页面左右内边距 `var(--ui-space-6)` = **24px**（`:28`）。数值同源，但**声明是两处**，没有共享同一个 gutter token，改一处就会漂。
- 行间距：`gap` 的纵向是 **0**（`:1041`）。两行之间实际视觉距离是「上卡 16 下 padding + 1px 分隔线 + 下卡 16 上 padding = 33px」，与横向 24px 不同节奏。
- 行高由内容决定：左 148 / 右 146（第一行），左 146 / 右 150（第二行）；`align-items:start`（`:1042`）让每张卡按自身内容高度结束，**没有共同底边**。
- `.dashboard-panel-schedule { grid-row: 2 / span 2 }`（`:1070`）跨两行，而第三行没有右列对应项；公告内容变高时，右列把行撑高，左侧日程卡不跟随拉伸，卡片下方出现空档——这就是截图里「一列长、一列短、中间大块空白」的机制。

## 3. 原始 5 个问题的成因

### 3.1 红色竖线（已更正为标注）

- 不是 DOM 元素，也不是设计 token：全仓搜索 `#F54A45` / `rgb(245,74,69)` 无结果；运行时遍历 `.react-workspace`、`.dashboard-workbench`、`.dashboard-board`、所有 `.workspace-panel` 及其 `::before/::after`，没有任何红色 border / inset shadow。
- 像素证据：线宽 8 原始 px（≈4 CSS px），起止两端为圆头渐隐，颜色 `rgb(245,74,69)`；同一红色还出现在截图工具右下角悬浮球。属于截图标注笔迹。
- 它指向的真实问题是 **左边缘不齐**，已在本报告第 1、2 节量化。

### 3.2 空状态三套写法

| 场景 | 组件 / 选择器 | 位置 | 形态 | 动作 |
|---|---|---|---|---|
| 工作台 4 个预览卡 | `.dashboard-empty`（`dashboard-todo.css:182-191`，契约层 `design-system-apply.css:1253-1261`） | 左上文案 + 整行宽按钮（文字居中） | 1px 虚线、`--ui-bg-subtle` 底、min-height 64、padding 12 | 「+ 新增待办」「+ 新增日程」「查看全部 →」「+ 发布公告」混用 |
| 列表页表格 | AntD `ant-empty` | 居中 | 40px 插图 + 「暂无数据」 | 无 |
| 审计日志 | `locale.emptyText` 字符串 | 居中 | 一行文字，无插图 | 无 |
| 待办列表页 | AntD `Empty` + 自定义图标 | 居中 | 32px 图标 + 「暂无待办」 | 无 |
| 详情页 | `.module-state.panel-empty-state`（`dashboard-todo.css:834-862`） | 居中 | 1px 虚线、`#FAFBFC` 底、220px、padding 28、gap 8 | 无（详情页动作在标题右侧） |
| 快捷入口 | `.dashboard-shortcut-empty` | 左对齐 | 无虚线框，标题 + 说明 + 4 个推荐瓦片 | 推荐瓦片可直接跳转 |

同一句「暂无待办」，工作台是「左对齐 + 整行按钮」，待办列表页是「居中 + 图标 + 无动作」；这就是用户感知的「三套写法」。另外，通知卡片的「查看全部」同时出现在面板标题右上和空状态按钮里，是重复入口。

### 3.3 快捷入口文案矛盾

`DashboardShortcutsPanel.tsx:143-168`：`shortcuts.length === 0` 时渲染

- 标题：`dashboard.shortcutEmpty` = 「还没有快捷入口」
- 说明：`dashboard.shortcutRecommended` = 「先从常用页面开始，点击即可跳转」
- 紧随其后：`recommendedShortcutTargets(menus)` 生成的 4 个瓦片（产品资料 / 工厂资料 / 客户资料 / 订单中心）

文案说「没有」，画面却有 4 个可点击入口。实际语义是「没有**自定义**入口，下面是**推荐**入口」，但缺少「推荐」这一层标签。

### 3.4 动作归属混乱

`DashboardPage.tsx` 的渲染顺序是：统计条 → 快捷入口卡片 → `.dashboard-toolbar` → 看板。`.dashboard-toolbar`（`DashboardPage.tsx:391-400`）是快捷入口卡片的**兄弟节点**，不是子节点，但：

- 它没有标题、没有分隔线、没有容器；
- 与快捷入口卡片只隔 12px（`.dashboard-workbench { gap: var(--ui-space-3) }`，`design-system-apply.css:977`）；
- 两个按钮是页面级全局动作（新增日程 / 发布公告）。

视觉上它读作「快捷入口卡片的第二行动作」，而不是页面动作。规范里页面级动作应放在 PageHeader 区域。

### 3.5 两列卡片底部不齐

实测：左列底 696.0，右列底 700.0（差 4px）；两行高度 148/146、146/150。机制：

1. `.dashboard-board` 是 3 行栅格（`grid-template-rows: auto auto auto`，`:1040`），第三行没有右列内容；
2. 左侧日程卡 `grid-row: 2 / span 2`（`:1070`），跨第二、三行；
3. `align-items: start`（`:1042`）让卡片不拉伸，高度随内容；
4. 右列公告一旦多行，第二行行高被撑大，左列卡片底边不跟随，形成底部空档；反之右列更高时，左列下方留白。

空数据态只差 4px，但结构上已经决定了「内容一变化就不齐」，不是单次像素误差。

## 5. 统一规则提案（确认后再动样式）

### 5.1 横向：容器只加一次内边距

- 新增两个 token（`design-system.css`）：
  - `--ui-page-gutter: 24px`（页面左右）
  - `--ui-card-inset: 16px`（卡片内容左右）
- `.react-workspace` 只负责 `--ui-page-gutter`；页面根节点、区块、卡片**不再写横向 margin**。
- 卡片内容左 = 卡片外框 + 1px 边框（如有）+ `--ui-card-inset`。边框差 1px 允许，同一页面内必须完全一致。
- 统计条外框与卡片外框同左（264）；统计内容与卡片内容同左（280/281）。
- 卡片内所有区域（标题、正文、空状态、表格容器）共用同一个 `--ui-card-inset`；**空状态不允许再叠 12px**。
- 列间距与页面左右 gutter 共用 `--ui-page-gutter` 一个变量，不重复声明。

### 5.2 纵向：4/8 节奏

- 允许值：**4 / 8 / 12 / 16 / 24 / 32**；布局间距禁用 7、9、13、14、15、18、20（1px 边框除外）。
- 页面根节点：`gap: 16px`（统一替代 12 / 14 / 16 三套）。
- 卡片：`padding: 16px`；标题区高 48 或 54（二选一，全站统一）；标题到正文 **12px**（现在列表页是 16 + 12 = 28）。
- 两列/多列：列间距 24；行间距与列间距同值（推荐 16 或 24），不再出现「横 24、纵 0」。
- 表格视为卡片内的**嵌套区域**：容器左边缘对齐卡片内容线，单元格 padding 16 由表格自己负责，不用页面 padding 去凑。

### 5.3 卡片结构（三段式）

所有卡片固定三段，二选一，不允许混用：

**A. 独立卡片**（列表页、工作台推荐）

- 外框：1px 边框、8px 圆角、白底；
- 标题区：高 48/54，`padding: 0 16px`，底部分隔线；标题图标 18 + gap 9；动作在右侧；
- 内容区：`padding: 16px`；
- 卡片间距 16/24。

**B. 分区列表**（仅当整页是一个连续面板）

- 无圆角、无白底、无左右边框；只有上分隔线；
- 标题区 `padding: 12px 16px`；
- 内容区 `padding: 0 16px 16px`；
- 同一列内 0 间距，列与列之间 24。

工作台目前是「A 的快捷入口 + B 的看板 + 卡片之间的工具栏」三种混用。建议工作台统一为 A：快捷入口、今日优先处理、我的日程、消息、公司公告都做成独立卡片，2×2 看板 + 16px 间距。

### 5.4 空状态组件

一个 `<EmptyState>`，两种密度：

- `page`：min-height 220，用于表格/详情；
- `compact`：min-height 96，用于工作台预览卡。
- 结构固定：图标 32（可选）→ 标题 14/20 → 说明 12/18 → **一个**动作（文字链接或次级按钮）；
- 居中；**去掉虚线边框和底色**（虚线/底色是当前「三套写法」的主要视觉来源）；
- 动作只能有一个：如果标题区已有同义动作，空状态不再重复；没有标题区动作时才在空状态给出；
- 表格通过 `locale.emptyText` 复用同一组件，保证「暂无数据 / 暂无待办 / 暂无消息」同形。

### 5.5 统计卡片

- 复用 `.summary-strip` 的 4/5 等分模型：`display:grid; grid-template-columns: repeat(var(--metric-count), minmax(0,1fr)); gap:1px;` 外框 1px、白底；
- 单元格：`padding: 12px 16px; min-height: 72px`；label 13/20，value 26/32，间距 6；图标 28；
- 列数由实际指标数量决定（4 或 5），不写死 5，也不用 `min-width` + `clamp()` 间距；
- 工作台直接改用该模型，可同时解决 118px 固定宽、57.6px 间距、右侧 503px 空白。

### 5.6 动作位置

- 页面级动作（新增日程、发布公告）→ PageHeader 右侧；
- 卡片级动作 → 卡片标题区右侧；
- 行级动作 → 行内；
- 禁止在两次区块之间放无标签工具栏；同一区域只保留一个主按钮。
