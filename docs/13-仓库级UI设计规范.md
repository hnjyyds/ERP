# 仓库级 UI 设计规范

## 1. 目标与适用范围

本规范是新裴贸易业务管理系统的 UI 事实标准，适用于 `frontend/src` 内所有页面、共享组件和新增功能。

产品面向外贸、采购、QC、仓库、财务和管理人员，属于长时间、高频率使用的操作型 ERP。视觉目标是：

- 实用：首屏显示当前任务、状态和主要操作。
- 可信：尺寸、对齐、颜色和反馈稳定一致。
- 精准：用颜色表达状态，不用颜色做无意义装饰。
- 安静：以浅色中性面为主，避免背景网格、发光、大阴影和多层卡片。

## 2. 事实源与优先级

1. `frontend/src/design-system.css`：视觉 token 和共享组件基线，最高优先级。
2. `frontend/src/app/theme.ts`：Ant Design 主题，必须与 CSS token 同值。
3. `frontend/src/styles.css`：页面结构和存量样式，不得重新定义全局色彩和尺寸。
4. 页面局部样式：仅允许处理业务特有布局，不得复制通用控件外观。

新增颜色、间距、圆角、阴影或字号前，先检查现有 token。只有当新值在三个以上场景复用时，才允许新增 token。

## 3. 如何判断“好”与“不好”

“好”不是某一种主观风格，而是界面对当前任务的支持程度。本仓库使用以下五个可验证标准：

| 判断维度 | 好 | 不好 | 验证方法 |
| --- | --- | --- | --- |
| 任务效率 | 两秒内找到主操作，一次扫视理解页面结构 | 所有按钮同样显眼，需要逐个阅读 | 请未参与开发的人口述“如何新增” |
| 信息层级 | 页面标题、面板标题、字段标签、数据有固定级差 | 整页普遍粗体，每个元素都在抢注意力 | 灰度截图中仍能识别阅读顺序 |
| 对齐秩序 | 同级控件共用基线、高度和列网格 | 使用空文字、不同宽度和局部 margin 凑对齐 | 在截图上画水平/垂直参考线 |
| 状态可读 | 颜色、文字和位置共同表意 | 只用红绿区分，颜色之外没有信息 | 模拟去色或色觉异常后仍可区分 |
| 长时间舒适度 | 亮度层级充足但对比克制，粗体和主色稀缺 | 边框、网格、粗体、强色同时大量出现 | 连续使用 30 分钟后主要数据仍易于扫描 |

### 3.1 对照例子：QC 筛选区的对齐

截图中的原实现使用两个带空白标签的 `label` 来将“查询”和“新增 QC 单”推到第二行：

```tsx
// 不好：空标签只是视觉占位，语义错误，按钮宽度也被字段列宽控制。
<label>
  <span>&nbsp;</span>
  <Button>查询</Button>
</label>
<label>
  <span>&nbsp;</span>
  <Button type="primary">新增 QC 单</Button>
</label>
```

这种做法的问题：

- 屏幕阅读器获得两个没有字段的标签。
- 只要上方列宽或字段数改变，按钮就会偏移。
- 按钮宽度来自筛选字段，而不是操作本身的重要程度。
- “查询”和“新增”在结构上是字段，导致视觉和交互层级不稳定。

优化后使用独立操作组：

```tsx
// 好：字段是字段，操作是操作；布局改变不会破坏语义。
<div className="filter-actions">
  <Button htmlType="submit" icon={<Search size={16} />}>查询</Button>
  <Button type="primary" icon={<Plus size={16} />}>新增 QC 单</Button>
</div>
```

```css
.filter-actions {
  display: flex;
  grid-column: 1 / -1;
  justify-content: flex-end;
  gap: 8px;
}
```

可测量结果：两个按钮高度都是 `36px`，间距 `8px`，与筛选字段有 `12px` 垂直间隔，右边线与表格右边线对齐。

### 3.2 对照例子：按钮层级

```text
不好
[查询：大白色边框按钮] [新增 QC 单：大蓝色按钮]
两者都占满一整列，面积接近，像两个同级主操作。

好
                                              [查询] [ + 新增 QC 单]
查询是次操作，新增是唯一主操作，按内容自适应宽度。
```

判断依据不是“蓝色更好看”，而是当前筛选条件改变频率高，查询是可重复的工具动作；新增会进入新任务流程，应当是该区域唯一主操作。

### 3.3 对照例子：字体重量

```text
不好：页面标题 800 + 面板标题 800 + 字段标签 700 + 表头 800 + 单号 800
结果：标题、筛选、表夼和数据同时突出，阅读起点不明确。

好：页面标题 700 + 面板标题 650 + 字段标签 600 + 表头 600 + 单号 600
结果：页面标题定位，面板标题分组，数据回到扫描主体。
```

截图中侧栏、“QC 任务列表”、字段标签和表格单号都明显偏粗，即是这个问题。优化不是把所有文字变细，而是恢复层级差。

### 3.4 对照例子：边界线与背景

```text
不好：
网格页面背景
└─ 有边框的面板
   └─ 有边框的筛选输入框
      └─ 有边框的按钮
         └─ 有水平线和竖线的表格

好：
中性页面背景 #f4f6f8
└─ 单层面板边界 #dfe3e8
   ├─ 输入框边界 #dfe3e8，聚焦时增强
   └─ 表格只保留表头和行分隔线 #e9ecf0
```

截图中页面网格穿过侧栏和工作区，同时侧栏分组、指标条、主面板、输入框和表格都有边界，视觉分割过度。优化后的原则是“外层定区域，内层靠留白”。

### 3.5 对照例子：亮度层级

| 层级 | 不好 | 好 | 原因 |
| --- | --- | --- | --- |
| 页面 | 白色加高对比网格 | `#f4f6f8` 无纹理 | 工作时间长，底色应稳定退后 |
| 面板 | 与页面接近，依赖阴影区分 | `#ffffff` + `1px` 弱边界 | 亮度差本身就能建立前后层级 |
| 表头 | 纯白或高饱和色 | `#f7f8fa` | 区分标题和数据，但不抢数据 |
| 选中 | 高饱和蓝底白字 | `#edf2ff` + 深蓝文字 | 选中态在长时间停留时仍不刺眼 |

### 3.6 对照例子：指标条是否有用

```text
不好：QC 任务 9 / 待查验 0 / 查验中 0 / 已完成 9 / 已取消 0
五个数字同等显眼，其中三个是 0，占用了大量首屏空间。

好：待查验 0 / 查验中 0 / 未通过 1 / 今日已完成 2
只呈现会影响当前排程、入库或风险决策的数字。
```

指标的好坏不取决于卡片是否精致，而取决于它是否支持当前决策。暂未调整指标口径时，至少应降低零值指标的视觉重量。

## 4. 基础 Token

### 4.1 颜色

| 用途 | Token | 值 | 规则 |
| --- | --- | --- | --- |
| 页面背景 | `--ui-bg-page` | `#f4f6f8` | 只用于页面和工作区底色 |
| 主面 | `--ui-bg-surface` | `#ffffff` | 表格、面板、弹层 |
| 弱面 | `--ui-bg-subtle` | `#f7f8fa` | 表头、侧栏、次级区域 |
| 选中面 | `--ui-bg-selected` | `#edf2ff` | 导航和表格选中 |
| 主文字 | `--ui-text-primary` | `#20242c` | 标题、正文、数据 |
| 次文字 | `--ui-text-secondary` | `#5f6875` | 辅助说明 |
| 弱文字 | `--ui-text-muted` | `#7c8592` | 占位、时间、非关键元数据 |
| 边界 | `--ui-border` | `#dfe3e8` | 面板和控件边界 |
| 弱边界 | `--ui-border-subtle` | `#e9ecf0` | 表格行、内部分隔 |
| 主操作 | `--ui-primary` | `#315bd6` | 主按钮、焦点、链接 |

状态色只用于状态标签、警告、错误和成功反馈。同一条信息必须同时包含文字或图标，不能只靠颜色表意。

### 4.2 字体与字重

| 层级 | 字号 | 字重 | 行高 |
| --- | --- | --- | --- |
| 页面标题 | `24px` | `700` | `32px` |
| 面板标题 | `18px` | `650` | `26px` |
| 分组标题 | `15px` | `650` | `22px` |
| 正文/控件 | `13px` | `400-500` | `20px` |
| 字段标签/表头 | `12px` | `600` | `18px` |
| 辅助信息 | `12px` | `400-500` | `18px` |
| 关键指标 | `22px` | `700` | `28px` |

禁止使用 `800/850/900` 作为常规页面字重。英文编号、中文名称和数值默认不加粗；只有当它是当前行的主识别信息时使用 `600`。

### 4.3 间距、高度与圆角

- 间距基数：`4px`；常用序列为 `4 / 8 / 12 / 16 / 20 / 24 / 32`。
- 桌面端工作区水平内边距：`24px`；移动端：`14px`。
- 常规控件高度：`36px`；紧凑控件：`28px`；移动端触摸目标：不小于 `44px`。
- 侧栏展开宽度：`240px`；常用导航行高：`36px`。
- 面板圆角：`6px`；控件圆角：`5px`；标签圆角：`4px`。
- 只有弹层允许使用弱阴影；常规页面面板不使用悬浮阴影。

## 5. 布局和对齐

### 5.1 页面结构

```text
Page
├─ PageHeader：业务归属、页面标题、页面级操作
├─ MetricStrip：可选，仅显示会影响当前决策的指标
├─ Feedback：错误、警告或成功反馈
└─ WorkspacePanel
   ├─ PanelHeader
   ├─ FilterBar + ActionGroup
   └─ Table / Form / Workflow
```

- 页面垂直间隔固定为 `16px`。
- 面板内边距固定为 `16px`。
- 标题、筛选区和表格的左边线必须一致。
- 不使用空标签、`&nbsp;` 或固定按钮宽度实现对齐。

### 5.2 筛选区

- 字段使用 CSS Grid，建议列宽 `minmax(160px, 1fr)`。
- 搜索框可以占两列，ID 或状态筛选占一列。
- 列表默认使用单行工具栏：关键词搜索、查询、唯一主操作和视图工具同排展示。
- 国家、信用、状态等低频条件默认收起，通过“高级筛选”图标按需展开；条件生效后必须在图标上显示启用数量，收起时不得丢失条件。
- 高级筛选必须提供一键重置；重置后立即刷新结果，不要求用户再次点击查询。
- 操作组与字段分离，默认右对齐。“查询”为次级按钮，“新增”为主按钮。
- 字段标签、输入框和按钮使用统一基线，不允许按钮比同行输入框更高。
- 条件超过 6 个时，首屏保留 3-5 个高频条件，其余收入“高级筛选”。

### 5.3 表格

- 表头高 `40px`，数据行默认 `44px`，紧凑行不小于 `36px`。
- 文本列左对齐，数值列右对齐，状态和单一操作可居中。
- 长编号可省略，但必须提供 Tooltip 或详情入口。
- 行主入口使用文本链接；行尾“查看详情”使用文字按钮，不加重复边框。
- 横向列过多时保留横向滚动，不在移动端隐藏关键列。

## 6. 组件规则

### 6.1 按钮

- 同一操作区只允许一个主按钮。
- 主按钮：创建、保存、提交、确认。
- 次按钮：查询、导入、导出、返回。
- 文字按钮：表格行入口、查看、辅助动作。
- 危险按钮：删除、作废、不可逆操作，且必须二次确认。
- 工具型操作优先使用 Lucide 图标，图标按钮提供 `aria-label` 和 `title`。

### 6.2 边框和背景

- 一个视觉区域最多只保留一层外边界。
- 面板内部使用留白和弱分隔线分组，不嵌套卡片。
- 页面背景不使用网格、径向渐变、光斑或装饰性纹理。
- 弱阴影只用于下拉层、气泡和弹窗，不用于常驻面板和按钮。

### 6.3 响应式

- `> 1180px`：完整侧栏，筛选区 4-6 列。
- `769-1180px`：紧凑侧栏，筛选区 2-3 列。
- `<= 768px`：顶部导航抽屉，筛选区单列，操作按钮双列或单列。
- 不隐藏新增、查询、审批、提交和详情入口。

## 7. 页面类型模板

| 页面类型 | 标准结构 |
| --- | --- |
| 主数据 | 标题 + 精简指标 + 筛选 + 表格 + 详情抽屉 |
| 销售/采购单据 | 标题 + 状态流 + 单据头 + 明细 + 审批动作 |
| QC/跟单 | 标题 + 异常指标 + 任务筛选 + 任务表 + 节点/异常详情 |
| 仓库 | 标题 + 待操作指标 + 计划/实际分区 + 库存影响 |
| 财务 | 标题 + 口径说明 + 台账筛选 + 台账表 + 核销/结算动作 |
| 报表 | 标题 + 时间/组织口径 + 关键数据 + 图表 + 下钻表格 |

## 8. 验收清单

每个页面合并前必须确认：

- 只有一个明确主操作，两秒内可被找到。
- 同行控件高度、标签基线和边界线对齐。
- 标题、正文、标签和表头的字号/字重符合本规范。
- 页面存在页面背景、面板和控件三级亮度。
- 没有嵌套卡片、装饰性渐变、大阴影或无意义粗体。
- 空状态给出下一步，加载不造成布局跳动，错误信息可修复。
- 键盘焦点可见，文字对比度符合 WCAG AA。
- 在 `1440px` 和 `390px` 宽度下无非预期溢出、重叠或关键功能丢失。
- `npm run lint`、`npm run typecheck`、`npm test` 和 `npm run build` 通过。

## 9. 新页面实施顺序

1. 确定页面类型和主任务。
2. 复用 `PanelTitle`、`Metric`、`FormSelect`、`ColumnViewControl` 等共享组件。
3. 用 `design-system.css` token 完成布局，不写一次性颜色和尺寸。
4. 先完成工作流和状态，再做视觉细化。
5. 按验收清单完成自检和可视回归。
