# 日志与故障排查

系统使用结构化 JSON 日志，并为每个 HTTP 请求分配一个 `request_id`。浏览器、Nginx
和后端通过同一个 ID 关联一次请求，排查时不需要依赖模糊的时间范围或错误文案。

## 分层职责

| 层级 | 代码位置 | 职责 |
|---|---|---|
| 日志基础设施层 | `backend/app/core/logging.py` | 请求上下文、格式化、敏感信息脱敏和进程级日志配置 |
| HTTP 可观测性层 | `backend/app/api/request_logging.py` | 生成或透传请求 ID，统计耗时，记录访问结果和未处理异常 |
| 认证上下文层 | `backend/app/api/auth_dependencies.py` | 认证成功后将用户 ID 绑定到当前请求日志 |
| 应用装配层 | `backend/app/main.py` | 在路由前注册中间件，记录数据库、演示数据和 MCP 生命周期 |
| 边缘代理层 | `deploy/nginx/nginx.conf` | 在后端不可用时仍生成关联 ID，并记录代理状态和耗时 |
| 容器运行层 | `docker-compose.yml` | 注入日志配置并限制日志文件容量和保留数量 |

依赖方向保持为“HTTP/认证层调用日志基础设施层”，日志基础设施不反向依赖业务模块。
业务服务如需补充领域事件，只使用标准库 `logging.getLogger(__name__)`，请求 ID 和用户 ID
会由上下文自动加入，不应在业务方法间手工传递。

## 最短排查路径

1. 在浏览器开发者工具的 Network 中选中失败请求。
2. 从响应头复制 `X-Request-ID`，例如 `f8be2484d6c14d9998101b54108e300d`。
3. 使用该 ID 检索后端日志：

   ```bash
   docker compose logs --since=30m backend-a \
     | grep 'f8be2484d6c14d9998101b54108e300d'
   ```

4. 如需确认代理链路，再检索 Nginx 日志：

   ```bash
   docker compose logs --since=30m nginx \
     | grep 'f8be2484d6c14d9998101b54108e300d'
   ```

后端日志会直接给出请求方法、路径、路由模板、状态码、耗时、客户端地址和当前用户 ID。
未处理异常还会包含完整堆栈。API 的 4xx 记为 `WARNING`，5xx 记为 `ERROR`，超过慢请求
阈值的成功请求也记为 `WARNING`。

## 常用查询

查看最近的后端错误：

```bash
docker compose logs --since=30m backend-a | grep '"level":"ERROR"'
```

查看慢请求：

```bash
docker compose logs --since=30m backend-a | grep '"slow_request":true'
```

查看某个用户相关请求：

```bash
docker compose logs --since=30m backend-a | grep '"user_id":"u-quality"'
```

持续观察日志：

```bash
docker compose logs -f --tail=100 backend-a nginx
```

## 关键字段

| 字段 | 含义 |
|---|---|
| `event` | 事件名称，如 `request_completed`、`request_failed`、`service_ready` |
| `request_id` | 单次请求的关联 ID，也是浏览器响应头 `X-Request-ID` |
| `user_id` | 已认证用户 ID；匿名请求为 `null` |
| `route` | FastAPI 路由模板，用于聚合同类请求 |
| `status_code` | HTTP 状态码 |
| `duration_ms` | 后端处理耗时，单位为毫秒 |
| `slow_request` | 是否达到慢请求阈值 |
| `exception` | 未处理异常的堆栈，仅在失败日志中出现 |

## 配置

Compose 支持以下环境变量：

| 环境变量 | 默认值 | 用途 |
|---|---:|---|
| `LOG_LEVEL` | `INFO` | 后端最低日志级别，可设为 `DEBUG`、`WARNING`、`ERROR` |
| `LOG_FORMAT` | `json` | `json` 适合容器检索，`text` 适合本地临时阅读 |
| `LOG_SLOW_REQUEST_MS` | `1000` | 慢请求阈值，单位毫秒 |
| `LOG_HEALTH_REQUESTS` | `false` | 是否记录成功的健康检查请求 |
| `LOG_MAX_SIZE` | `10m` | 单个容器日志文件的最大容量 |
| `LOG_MAX_FILES` | `5` | 每个容器保留的日志文件数 |

修改配置后重建或重启后端容器：

```bash
docker compose up -d --build backend-a nginx
```

## 安全约束

请求日志不记录请求体、Cookie 或完整请求头。结构化日志中的密码、令牌、Authorization、
API Key、Cookie 和 Secret 等敏感字段会自动替换为 `[REDACTED]`。业务代码仍不应主动
将原始密码或凭据拼入普通日志消息。
