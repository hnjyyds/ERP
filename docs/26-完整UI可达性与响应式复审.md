# 完整 UI 可达性与响应式复审（2026-11-13）

## 对上轮漏检的纠正

工作台日程被截在屏幕下方、鼠标无法滚到，是基础 UI 缺陷，上轮审核应该发现。

上轮主要验证了页面入口、初始截图、部分组件尺寸和横向溢出，没有把**实际滚轮操作后能否到达末尾内容**作为逐页必测项，也没有完整覆盖小屏表单与浮层。因此，“页面能打开、未发现桌面横向溢出”不能用作完整 UI 验收依据。既有单元测试通过也不能补足这一缺口。

本轮重新采集现场，不沿用上轮的页面通过标记。当前新加载版本已解除工作台外层高度/overflow 锁定；在三种视口中，日程、消息、公告均能滚到。该历史故障记为**已修复**，不重复算作当前未修复问题。本轮没有修改业务代码或部署容器。

### UIR-01 商品页工具条撑宽整页

390px视口下，文档宽 **1014px**。查询按钮在x=31，新增在x=75；导入、导出按钮各宽384px，列设置在x=978。搜索框本身也宽384px，超过卡片内可用宽度。

影响：常用操作跑到屏幕右侧，用户必须横移整页才能寻找；这不是表格列多所需的局部滚动。商品表格自身可以局部滚到最右侧，不能把整页撑宽归咎于表格。

根因位置：[design-system-apply.css](../frontend/src/styles/design-system-apply.css) 中`product-filter-actions`在手机断点仍`flex-wrap:nowrap`，与按钮尺寸规则和Grid最小内容尺寸叠加。

建议：操作组在小屏换行/按明确网格组织，按钮内容定宽，字段轨道使用可收缩尺寸；不能用`body overflow:hidden`遮掉右侧，那会重新制造内容不可达。

证据：[商品页手机首屏](checks/ui-content-2026-11-13/390/06-_masterdata_products-top.png)、[页面尺寸记录](checks/ui-content-2026-11-13/results.json)。

### UIR-02 手机三列表单字段过窄

确认范围：商品、供应商、客户、合作伙伴、单证、出口合同、采购合同、来源出口合同生成采购、样品登记、打样、寄样，共11类创建/配置表单。5类已有资料的编辑模式也复现了同形布局。

| 表单族 | 普通字段宽度 | 用户影响 |
| --- | --- | --- |
| 主数据五类 | 约77px | 名称、邮箱、地址/银行字段只能看到开头 |
| 出口/采购及采购生成 | 约77～78px | 日期、付款条款、客户名称难以核对 |
| 样品三类 | 约82px | 收件人、收件地址、日期、商品名称过于拥挤 |

这些字段可以滚动到达，但可达不等于可读。正常日期、客户名称都不应靠在狭窄输入内反复移动光标才能辨认。

根因：

- [masterdata-pages.css](../frontend/src/styles/masterdata-pages.css) 的`@media(max-width:760px)`单列规则在约185行，后面约247行又声明同等优先级的三列`.entity-modal-grid`，把手机回退覆盖。
- [shared-primitives.css](../frontend/src/styles/shared-primitives.css) 的`.contract-modal-form .form-row`固定三列，缺少有效的小屏回退。
- [sample-pages.css](../frontend/src/styles/sample-pages.css) 的`.sample-modal-form`固定三列，没有形成有效的小屏列规则。

建议：把小屏布局规则放在能实际生效的层级，手机以单列为主，短字段需要并排时才使用明确的双列变体；不要通过继续缩字号容纳三列。

证据：[出口合同](checks/ui-content-2026-11-13/modals-390/export-bottom.png)、[真实客户编辑](checks/ui-content-2026-11-13/edits-390/customers-top.png)、[样品寄送表单](checks/ui-content-2026-11-13/modals-390/sample-delivery-top.png)。

### UIR-03 金额的最后一位被换到下一行

采购详情在390px下，进度概览把`RMB 250.00`显示成`RMB / 250.0 / 0`。币种与金额分行尚可理解，但小数被拆开，容易误读。

根因线索：[finance-reporting.css](../frontend/src/styles/finance-reporting.css) 对`.compact-table th, .compact-table td`统一使用`overflow-wrap:anywhere`；窄列缺少数值类型保护。

建议：数值字符串不可从小数中间断开；必要时表格放进局部横向滚动容器或改成小屏摘要。不能对所有文字一律nowrap，否则可能制造新溢出。其他共用compact-table是影响面，不直接记为全部复现。

证据：[采购详情手机底部](checks/ui-content-2026-11-13/details-390/purchase-bottom.png)。这项针对合法250.00金额的排版，不把历史测试中的异常账务当成新UI缺陷。

### UIR-04 “今日日程”计数不按今天过滤

测试当天为2026-11-13（Asia/Shanghai）。工作台显示“今日日程 2”，预览两条分别为11月12日19:00和11月13日12:00，其中一条明确标记已结束。

源码 [dashboard/services.py](../backend/app/modules/system/dashboard/services.py) 将`today_schedule_count`直接设置成`len(schedule_events)`；[repositories.py](../backend/app/modules/system/dashboard/repositories.py) 的日程查询只按用户筛选，没有今天的日期范围。

建议：若指标意图是“今日”，按用户时区计算日界线并处理跨日事件；若意图是全部个人日程，改名，不能混用口径。无需新造日程即可复现。

证据：[工作台顶部](checks/ui-content-2026-11-13/1440/01-_-top.png)与[滚到日程](checks/ui-content-2026-11-13/1440/01-_-bottom.png)。

### UIR-05 中文页面泄漏通知状态码

审批通知旁直接显示`success`，而同一区域的“已读”“处理”均为中文。来源是[statusTags.tsx](../frontend/src/app/pages/helpers/statusTags.tsx)的`severityTag`：只映射high/urgent/warning/info，未知值直接显示原值，success还会落入默认蓝色。

建议：补全后端实际会返回的状态/严重度映射，并给未知值提供面向用户的兜底文本。证据见工作台日程底部截图右侧消息卡。

### UIR-06 搜索提示过浅

非禁用商品搜索框的placeholder现场颜色为`rgb(191,194,204)`，不透明度1，背景白色；按相对亮度计算约 **1.78:1**。提示承载“编号/中文/英文/海关编码”的检索范围，过浅影响阅读。

建议：使用可读的辅助文字颜色；区分正常提示与禁用态，不对所有placeholder硬编码同一个浅灰`!important`。本轮不是全站无障碍合规认证。

证据：[现场样式](checks/ui-content-2026-11-13/placeholder.json)、[antd-and-login.css](../frontend/src/styles/antd-and-login.css)的placeholder规则。

### UIR-07 手机通知浮层越界

390px下动画结束后的Popover边界为x=-12、宽344、右边332。内容面板从x=0开始，左侧边框/留白被裁掉，与页面其余卡片的安全边距不一致。

源码：[NotificationBell.tsx](../frontend/src/app/components/topbar/NotificationBell.tsx)使用bottomRight；[base-shell.css](../frontend/src/styles/base-shell.css)将内部面板固定为320px，叠加浮层padding后为344px。

建议：限制浮层宽度并允许在视口内平移；按浮层本身的边界验收，不能只看正文是否还剩在屏幕里。

证据：[稳定边界](checks/ui-content-2026-11-13/notification-bounds.json)、[截图](checks/ui-content-2026-11-13/targets/notification-390-stable.png)。

### UIR-08 手机图标按钮的触摸宽度不足

商品查询、列设置按钮仍为 **36×44px**：高度进入手机规格，宽度保留桌面36px。展开导航后，最后“开票通知”链接实测346×36px，也没有达到手机高度。现有[仓库UI规范](13-仓库级UI设计规范.md)规定移动端触摸目标不小于44px。

建议：为图标按钮同时指定手机宽高，不只改min-height，并核对导航链接的手机行高。已确认的是商品两个工具按钮和导航末项，不推断所有按钮或导航项都相同。导航测量见extra-results.json。

## 如何避免再次漏检

以后每个UI场景分别记录四个结论，不能只留一个“通过”：

1. **入口可打开**：正确进入页面或弹窗。
2. **内容可达**：实际滚轮到末尾；检查隐藏裁切祖先、内部与外部滚动、局部横向滚动。
3. **内容可读**：检查字段/日期/金额是否因缩列、断字或过低对比度而失去可读性。
4. **操作可定位**：按钮在可达位置且没有透明层/固定层遮住；只读检查不点击提交。

每次都保留视口实测值、滚动前后位置和证据截图。1440/1280/390三档不得只跑一个桌面宽度；长表单和现有数据详情必须单独检查。对带多个操作段的表单检查各段位置，不把“当前不在屏幕”直接判成“滚不到”。

## 本轮限制

本轮针对当前管理员、现有数据、列表/创建配置/可用编辑/详情状态；没有新增业务数据，没有审批/保存/上传/权限修改。空态、校验展开后的错误态、全部角色、原生浏览器缩放和全量辅助技术测试尚未穷尽，不能宣称整个应用所有状态都通过。

浏览器翻译插件的粉色浮标、代理光标等不作为本项目UI缺陷。原有测试产生的异常账务只用于现有详情展示，未重新执行并发或账务测试。
