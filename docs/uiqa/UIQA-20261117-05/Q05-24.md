# Q05-24：远程选择器聚焦后已选值被白底输入层遮挡，字段显示为空

级别P2；版本`index-By6s5oGf.js`；admin；`/sample/records`新增样品表单；1440×900、390×844；未提交。

操作：在“产品”中检索并选中`UIQA-20261117-05-P17`，或在“客户”中选中`QA261112 测试客户`后保持焦点。字段在页面上显示为空白，只有光标；失焦后已选值才重新出现（长名以省略号截断并保留完整title）。

实测数据：聚焦时选择器内部的搜索输入框宽365px（客户字段264px），背景为`rgb(255,255,255)`不透明，正好覆盖同样宽度的已选值文本层；失焦后该输入框背景变为`rgba(0,0,0,0)`，文本恢复可见。DOM中已选值始终存在，表单值和提交数据未丢失。

预期：聚焦只表达边框/光圈，不应遮住当前已选值；用户点击字段准备修改时必须能看到当前选的是什么客户或产品。

根因（源码与部署产物一致，不是旧构建差异）：[design-system-apply.css](file:///Users/dev/Documents/新裴贸易/frontend/src/styles/design-system-apply.css#L694) 的聚焦规则`body .record-form input:focus`未排除`.ant-select-input`，把内部搜索框刷成`var(--ui-bg-surface)`且带`!important`；它与第352行`.ant-select-input`透明规则特异性相同、位置更靠后，因而胜出。第349-351行注释已写明“不能绘制该内部输入框，否则已选值被视觉隐藏”，此处是同一问题的回归。

（路径中的`#L694`仅作定位，不影响阅读。）

影响面（实测与推定分开登记）：

- 已实际复现：PAGE-12样品登记FormModal内的`RemoteSelect`（产品、客户，1440×900与390×844）；PAGE-01商品新增FormModal内的普通AntD“状态”Select（1440×900）。商品状态下拉聚焦时内部输入框258.66px、白底`rgb(255,255,255)`，与内容层同宽并遮住“启用”；点击商品编号失焦后输入框变透明、文字恢复。
- 源码推定（未逐页实测）：`FormModal`把所有子表单包在`.record-form`内，因此商品、基础资料、单证、样品、出货、采购、QC、入仓/出库工作流及计划生成等表单中的AntD Select与RemoteSelect均可能命中。该清单只作影响面登记，不能算作这些页面已经实测。
- 列表页筛选栏不在`.record-form`内，按选择器作用域不触发；P19入库筛选可正常选中并显示标签，但未单列聚焦态测量。

## 修复与部署复验（2026-11-18，已关闭）

第一次修复只处理了聚焦规则（`body .record-form input:focus` → `:not(.ant-select-input)`），部署到`index-CWFbyr-R.js`后复测发现：键盘聚焦时已选值可见，但**鼠标悬停时内部输入仍被刷成白底并覆盖已选值**，原缺陷在真实点击路径上依旧存在。因此该次“只看内部输入无边框/光圈”的结论不成立，本轮按新口径重测。

- 第二次修复补充`body .record-form input:not(.ant-select-input):not(:disabled):hover`与`body .record-form input:not(.ant-select-input):disabled`，悬停/禁用态也不再给选择器内部输入铺背景；聚焦与悬停只由容器边框/光圈表达。
- 部署复验（`assets/index-DTcfpjkq.js`、`assets/index-CVMx6kR8.css`）：
  - 样品表单“产品”`RemoteSelect`：选中`UIQA-20261117-05-P17`后保持聚焦并悬停，内部输入背景`rgba(0,0,0,0)`，已选值文字在字段内可见；ArrowDown 打开候选、Escape 关闭后值仍在；Tab 离开后仍可见。1440/1280/390 三档一致。
  - 样品表单“客户”`RemoteSelect`：选中`QA261112 测试客户`，1440/1280 聚焦+悬停时已选值可见。
  - 商品新增“状态”与“付款方式”普通 AntD Select：聚焦后“启用”“按供应商分单”可见，ArrowDown 可打开候选。
