# Q05-33：出货财务概览利润未按应收−应付重算，利润率超过 100%

P2，已修复，2026-11-19 复验关闭。index-jJamVJA9.js（449aaa0a+工作区补丁）。对象：出货单 SP-DAEPEG（d6fc976b-09f5-41e4-a3b3-7aba1f636621）。

## 现象

出货列表卡片、详情概览与 `/api/v1/sales/shipments/{id}` 均返回：

- 应收金额 USD 205.00
- 预计付款 USD 0.00
- 预计利润 USD 210.00
- 利润率 102.44%

按仓库既有计算规则 `profit_amount = receivable_amount - payable_amount`，利润应为 205.00、利润率 100.00%。当前利润比应收高 5.00，利润率超过 100%，与同页“预计付款 0.00”自相矛盾。

出货行金额为 20 pcs × USD 10.25 = USD 205.00，未发现可解释 210.00 的成本或收入项。

## 预期

利润与利润率随应收/应付变化重算，或明确展示利润的独立来源；不允许出现利润大于应收且成本为零的组合。

## 证据

[出货整页验收](P09-accept-list-20261118.json)、[详情财务概览](screenshots/P09-acc-detail-1440.png)。接口原值：`finance_overview.receivable_amount=205.00, payable_amount=0.00, profit_amount=210.00, profit_rate=102.44`。

## 影响

出货列表、出货详情、财务概览与老板看板若复用同一字段，会同步放大。未修改数据、未重新审批出货单。

## 原因与修复（2026-11-19）

**根因**：利润存在两条写路径。`refresh_finance` 按来源整体重算；退税登记走 `add_refund_to_shipment_profit`，在旧利润上增量 `+=`。增量路径不幂等：来源（退税/应付/行金额）变化后不会从来源重新推导，后续任一次重算又会覆盖增量结果，派生值因此可能与来源长期脱节。SP-DAEPEG 现存退税 10.00，但利润停在 210.00（= 205 + 5），无法由当前来源复现，属于派生值漂移，而不是利润率公式本身。

**修复**：

- 利润统一按 `应收 − 应付 + 已登记退税` 重算；退税登记不再累加，改为调用同一重算方法。
- 利润率分母改为 `应收 + 已登记退税`（退税也是收入），避免零成本时凭公式出现 >100%；未做“截断到 100%”的掩盖。
- 迁移 `0022_recalc_shipment_finance` 对全部存量出货单重算应收、利润、利润率，覆盖已有记录。

**复验（index-jJamVJA9.js）**：SP-DAEPEG 应收 USD 205.00、应付 USD 0.00、已登记退税 USD 10.00，页面与接口均为利润 USD 215.00、利润率 100.00%，列表卡与详情一致。自动化：`pytest` 621 passed，新增“历史利润漂移经重算修复”用例。
