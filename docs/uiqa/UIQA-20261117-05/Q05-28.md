# Q05-28：列表加载失败被显示为“首次未建档”空态，且无重试入口

级别P2；原缺陷版本`index-By6s5oGf.js`；最新复验`index-DJFI-T9o.js`；admin；PAGE-01商品资料、PAGE-09出货明细、PAGE-24付款管理（含应付账款区）；1440×900（P09另含390×844）；只读，未写入业务数据。状态：**已关闭**（2026-11-18，四区失败→解除→重试→恢复均在`index-DJFI-T9o.js`重跑通过）。

## 实际表现

1. PAGE-01：阻断`masterdata/products?limit=50`后刷新，顶部统计变为商品0/配件0/有图0件，表格显示“还没有商品资料”“完成首次录入后，这里会显示对应记录”，页面同时暴露原始文本`Failed to fetch`，没有重试入口。解除阻断后刷新恢复50行。
2. PAGE-09：阻断`sales/shipments?limit=50`后刷新，统计出货单0/待审批0/已审批0/应收USD0.00，表格显示“暂无数据”“完成首次录入后，这里会显示对应记录”，暴露`Failed to fetch`，无重试。解除后恢复1行。
3. PAGE-24：阻断`finance/supplier-invoices`后刷新，供应商发票区显示“暂无数据”“完成首次录入后，这里会显示对应记录”；同页应付账款查询仍显示2行（该区请求正常）。解除后两表均恢复2行。

同页另一区正常本身不矛盾；错误在于把**请求失败**的发票区表述成“没有数据/完成首次录入”，使用户误以为该区从未建档，而不是加载失败。

预期：加载失败应有独立错误态，说明失败原因、保留当前筛选范围并提供重试；不得复用“尚未首次录入”的建档空态，也不应把原始`Failed to fetch`直接暴露为最终文案。加载失败属于读取失败，不是D09的保存失败，故本缺陷关联A05，不关联D09。

## 根因

列表空态组件仅按“是否带筛选条件”二分：[ListEmptyState.tsx](file:///Users/dev/Documents/新裴贸易/frontend/src/shared/ui/ListEmptyState.tsx#L29-L58) 在`filtered=false`时固定渲染`common.empty.noDataDescription`（“完成首次录入后……”）与创建入口，没有`error`分支或重试回调。请求失败时调用方没有把错误传给空态组件，错误文本只由全局提示暴露。

## 证据

[三页失败态汇总](load-failure-states-20261118.json)、[P01测量](P01-closeout-20261118.json)、[P09测量](P09-closeout-20261118.json)、[P24测量](P24-closeout-20261118.json)、[P01截图](screenshots/P01-list-load-error.png)、[P09截图](screenshots/P09-list-load-error-390.png)、[P24截图](screenshots/P24-list-load-error.png)。

## 建议

为空态组件增加`error`与`onRetry`；列表请求失败时保留页面框架与筛选条件，显示“加载失败/重试”，不要把失败折叠为“首次未建档”。修复后复验三页的默认、加载中、失败、重试、恢复，以及带筛选条件时的失败文案。PAGE-24另有Q05-02（权限拒绝显示为无匹配）与Q05-19，分别复验。

本轮只记录，未修改源码或数据。

## 修复与部署复验（2026-11-18，部分修复，未关闭）

- `ListEmptyState` 增加`error/onRetry`：加载失败显示“加载失败 + 数据读取失败，请重试；当前筛选条件会保留 + 重试”，优先于“筛选无结果/尚未首次录入”。
- 商品、发货单、供应商发票三处列表在请求失败时置错误态并提供重试；成功或重新请求时清除。
- 测试：三个页面均新增“加载失败→重试恢复”用例，前端415通过。
