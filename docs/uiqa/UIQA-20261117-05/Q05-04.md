# Q05-04：关联资料仍要求手填内部标识，开票通知预置演示关联

状态：**已关闭**（2026-11-18，原缺陷全部影响面已修复并复验通过；D02整项的其余未测场景继续保留，不折算为规范整项通过）。严重度 P2。原缺陷版本 index-By6s5oGf.js；2026-11-17；admin/超级管理员。最新复验 index-BawyFJj7.js；2026-11-18。

## 路径与复现

从各页菜单进入，打开新建表单，查看关联字段；三档1440×900、1280×720、390×844均留有表单及末端证据，未提交这些表单。

- 单证资料 `/masterdata/document-parties`：新建提供可编辑的“关联客户 ID”和“关联客户名称”，没有按业务客户名称/编号检索的关联选择入口。
- 出口报价 `/sales/quotations`：客户已有选择器，但商品仍为“商品标识、商品编号、商品名称、规格、型号”等独立输入框；用户需要手工建立关联及同步字段。
- 开票通知 `/purchase/invoice-notices` → 生成开票通知：供应商标识默认 `supplier-pack-a` / `supplier-label-a`，采购合同号默认 `PC-2026-PACK-A` / `PC-2026-LABEL-A`，商品编号 `BAG-40` / `LABEL-01`，数量1000/450、金额5200/360。新建不是从现有业务资料中选择。DOM中的采购合同ID、商品ID分别为 `pc-pack-a` / `pc-label-a`、`product-bag` / `product-label`；这两类输入位于 visually-hidden 区域，普通用户看不到。

预期：按业务名称/编号选择当前资料，关联标识与名称等派生值由同一选择结果更新；首次新建默认值符合当前业务上下文，不携带未选择的演示关联。

实际影响：正常用户无法仅凭业务资料完成可靠关联；开票通知可见编号与不可见内部标识是独立字段，有误关联风险。本轮没有提交该默认表单，**不声称已发生错误业务写入**。

违反：D02；开票通知同时不满足D01合理默认值。A02涉及的内部标识输入不属于审计用途。
