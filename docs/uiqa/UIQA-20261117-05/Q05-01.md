# Q05-01 商品必填字段说明及错误定位不足（P2）

当前版本index-By6s5oGf.js，商品新增，超级管理员，桌面窗口。英文名称及包装资料标签不标必填；填写已标必填的编号、中文名称、单位、海关编码后提交，服务端返回422并指出en_name/package_info不能为空。前端只显示“信息填写不完整或格式有误，请检查后重试”，没有这两字段的常驻具体错误或aria-invalid。

违反D04/D05：用户无法从表单确定仍缺哪些字段；聚焦/补填目标不明确。首次尝试曾填英文名但未填包装资料，同样未创建；确认无同编号记录后，再次带监测提交取得具体422证据。补齐两字段后保存和刷新详情成功，不能将此问题误记为所有正常保存均失败。

证据：[请求/响应](P01-create-network.json)、[字段标记](P01-server-validation-fields.json)、[界面](screenshots/P01-create-observed.png)、[补齐后详情](screenshots/P01-new-detail.png)。

预期：与服务端约束一致标注必填，并把响应中的字段错误就地显示、保留及引导焦点。根因尚未作实现级定位，本轮不修改代码。

## 共享基础资料表单补测

2026-11-17同版本，P02供应商、P03客户、P04合作伙伴新建空提交均仅显示“请填写编号”的3秒提示。等待提示消失并移焦，编号等必填字段没有常驻错误、红框或aria-invalid，字段也未标星。实际提交由前端校验拦截，各次新增网络非GET请求数为0，未产生新业务记录。此分支与商品后端422分开记录，均违反D04/D05。

证据：各页`P02/P03/P04-required-toast.txt`、`*-required-persistent.json`、`*-required-validation.json`及同名截图。取消未保存的UIQA编号草稿后重新打开，编号/名称为空、状态默认启用；该取消恢复子场景独立记录，不抵消校验缺陷。

## 商品配件子表补测

UIQA-P01的配件名称留空，其他字段为单耗1.25、单位pcs、默认供应商QA261112测试供应商。UI提交返回422，字段明细明确accessory_name不能为空；提示消失后表单仍没有常驻字段错误或必填标记。其余草稿保留，补填UIQA-20261117-05-A01测试配件后POST201，刷新仍为1.2500pcs，独立记录失败恢复/保存成功。证据：[422响应](P01-accessory-required-network.json)、[提示消失后](screenshots/P01-accessory-error-after-toast.png)、[保存响应](P01-accessory-save-network.json)、[刷新回读](P01-accessory-reloaded.json)。

联系人新建及单证资料新建补测：三类联系人空姓名均前端拦截（未发出联系人POST），仅toast；单证资料依次留空编号、显示名称、国家也仅toast，未发出业务POST。字段错误常驻与必填标记仍不满足。证据各页`Pxx-contact-required-persistent`、`Pxx-contact-required-network.json`，以及`P05-required-code/name/country`、`P05-required-persistent`、`P05-required-network.json`。单证引用停用客户返回409属于正确业务拒绝，另记失败恢复场景，不作为后台错误。

- 商品新增表单：服务端要求的英文名称、包装资料纳入客户端必填校验，字段就地显示错误并带`aria-invalid/aria-describedby`；编辑历史记录不因旧数据缺字段被拦截。英文名/包装资料在新建时显示必填标记。

## 全部表单补齐与部署复验（2026-11-18，已关闭）

部署资源`assets/index-BAsZmyiU.js`（前端工作区补丁，后端`b370c0fe`）后，按原失败路径逐表单空提交并逐字段补填：

- P02供应商、P03客户、P04合作伙伴：空提交均就地显示“请填写编号”，带必填星号、`aria-invalid`与`aria-describedby`并聚焦编号；补填编号后错误立即收起，再提交提示“请填写中文名称”。合作伙伴多一个必填的合作伙伴类型。
- 联系人新增：空姓名提交就地显示“请填写联系人姓名”并聚焦，补填后立即收起。
- P05单证资料：依次就地提示“请填写编号”→“请填写显示名称”→“请填写国家/地区”，均聚焦对应字段；补填后错误收起。
- 商品配件弹窗：空提交提示“请填写配件名称”，清空单耗提示“请填写大于0的配件单耗”，均定位到对应输入。
- 商品新建内联配件：主字段填齐、配件只填单耗1.25却缺名称时，提示“已填写配件信息，请补充配件名称或清空配件信息”并聚焦；不再像旧实现那样静默丢弃配件或由服务端422只返回全局提示。

所有校验均在前端拦截，未发出新增请求，未新增商品、配件、联系人、单证资料。自动化：前端418项通过（含新增字段级错误用例）、`tsc --noEmit`通过、改动文件eslint无错误。

边界：本轮覆盖本缺陷已登记的全部必填路径；服务端若对其他未被客户端覆盖的约束返回字段错误，仍以全局提示呈现，不属于本缺陷记录场景。
