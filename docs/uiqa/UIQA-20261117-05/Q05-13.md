# Q05-13：采购合同“采购员”错误使用质检人员候选

P2，已修复并部署复验关闭。修复前 index-By6s5oGf.js；复验 index-0SPe5fY1.js；实际账号purchase（演示采购专员）；三档1440×900、1280×720、390×844。

路径：采购合同 → 新增采购合同 → 采购员；以及采购合同 → 从出口合同生成 → 采购员。

原缺陷：候选只有系统管理员、演示业务主管和演示QC专员，三档输入“采购”均显示“暂无可选用户”，无法选择当前启用的采购专员。同一账号在采购询价的人选中可找到并选中“演示采购专员（采购部）”，不是账号不存在。

真实UI加载人员时请求`/api/v1/auth/users?required_permission=quality%3Ainspection%3Aedit`，200返回上述3人，排除拥有采购合同编辑权限而没有质检编辑权限的purchase账号。没有提交新采购合同或调整任何账号权限。

检查项：D02/C03/F05的人员分配子路径。

## 修复

- 候选加载拆分为两条独立请求：采购员用`purchase:contract:edit`，QC负责人继续用`quality:inspection:edit`。
- 手工新增与从出口合同生成两条表单的采购员/QC字段分别使用各自数组，姓名回填也分别查各自数组，避免选值后回填到错误对象。
- 未通过给purchase账号增加质检权限绕过问题，未调整任何账号权限。

源码：`frontend/src/app/pages/purchase/hooks/usePurchaseContractOptions.ts`、`usePurchaseContractFormModal.ts`、`components/PurchaseContractFormModal.tsx`。
