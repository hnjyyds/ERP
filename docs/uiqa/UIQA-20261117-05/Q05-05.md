# Q05-05：经营总览把已收票金额计入“待收税票金额”

严重度 P2；状态：刷新复核后确认，待修复。角色admin/超级管理员，2026-11-17，资源index-By6s5oGf.js。

页面：`/finance/overview`。1440×900、1280×720、390×844。

当前开票通知样本：两个草稿金额均CNY0.00；PIN-UIQA-20261117-04-01已收票，金额CNY0.01。经营总览“采购开票通知”表对应显示草稿2/0.00、已收票1/0.01；下方“合作伙伴费用入口”的“待收税票金额”仍显示0.01。

预期：已收票不再计入待收税票金额。本样本待收金额应为0；若该指标实际表示全部通知金额，应按实际口径命名，并标注币种。

实际：已收票金额与“待收”统计相矛盾，可能误导催票工作。此问题不否定此前已收票、发票保存和0.01付款闭环的实际成功结果。

检查项：A03、F02。没有为复现新增或修改单据。

证据：[经营总览快照](P31-list-1440.txt)、[页面明细清单](P31-list-inventory.json)、[手机底部截图](screenshots/P31-list-end-390.png)、[已收票通知详情](P11-detail-inventory.json)。

辅助定位：本地`backend/app/modules/finance/overview/services.py`将全部invoice_statuses金额相加为invoice_notice_amount；`frontend/src/app/pages/finance/views/FinanceOverviewView.tsx`将该值放入pendingInvoiceAmount标签。部署后端没有可验证的commit标签，因此该源码关系为修复定位依据，不代替当前UI观察。

建议：明确指标口径，按待收状态计算或更正标签；回归草稿/已发送/已收票和多币种样本。本轮尚无多币种通知样本，不声称已实测跨币种累加问题。
