# Q05-02 财务角色的关联选择被权限拒绝，却显示无匹配（P2）

版本index-By6s5oGf.js。账号finance_manager，页面设置确认“演示财务主管 / 财务部 / 财务”。路径/finance/payments。

步骤：财务角色进入付款管理→发票登记→分别打开供应商、开票通知、采购合同。三个来源接口均返回403，消息分别为缺少供应商、采购开票通知、采购合同权限；前端下拉统一呈现“无匹配结果”。刷新后重复相同安全路径仍成立。

这不是缺少种子数据：同版本管理员已经查看/选择过这些对象。财务角色可进入并使用发票登记入口，但其必要关联资料不可选，且权限错误被呈现为空搜索结果。违反A05、C03、D02、F05。没有绕过权限或尝试直接调用业务API。

证据：[角色](P24-finance-manager-role.txt)、[首次状态](P24-finance-role-source-status.json)、[403响应](P24-finance-role-forbidden-body.json)、[稳定空候选截图](screenshots/P24-finance-role-forbidden-repeat.png)。其他两个候选截图见P24-finance-role-notice-options、P24-finance-role-contract-options。

建议按财务业务授权提供最小范围的关联选项读取，或把真实权限条件明确呈现；不要简单以管理员结果代替财务角色验收。本轮不改角色或权限。其他角色/页面影响面继续检查，尚不从这一页推断全站。

## 实际角色扩展复核

finance（演示财务，实际财务view/edit/approve三项权限）也在发票登记的供应商、开票通知、采购合同来源遇到403，并显示无匹配。证据：`role-finance-profile-menu.json`、`role-finance-source-status.json`和`role-finance-create-combo-6/7/8-open`。

warehouse（演示仓库专员，有入库查看/编辑/审批权限）在入仓列表的供应商、采购合同筛选中调用已审批采购合同列表，同样403“缺少采购合同权限”。证据：`role-warehouse-profile-menu.json`、`role-warehouse-filter-status.json`、`role-warehouse-filter-供应商/采购合同`。问题限于已实测的跨模块筛选来源；生成面板仍能展示仓库计划中已有的已关闭合同项，该项禁用符合状态，不将其误报为空候选。缺少新可执行计划的生成闭环仍为未测，没有调整库存。

对照：QC角色有采购合同查看权限，QC中心更多筛选中的供应商从采购合同派生，真实请求200；不是所有业务角色的下拉都失败。没有通过修改角色权限绕过缺陷。

## 修复与部署复验（2026-11-18，已关闭）

- 新增受限权限`masterdata:reference-option:view`（关联选项读取），仅授予财务；开票通知另用`purchase:invoice_notice:option:view`，只授予财务；仓库仅获得供应商与采购合同选项读取。三个列表读取接受受限权限或原模块查看权限。
- 财务可用受限权限为发票登记选择供应商/开票通知/采购合同，仓库可用于入仓筛选；**不因此获得对应模块菜单，也不获得打印模板等功能**。
- 测试：财务读取三个来源200、打印模板仍403、QC供应商列表仍403、仓库开票通知403；菜单断言保持原样。后端617通过。
- 部署复验：财务登录后侧栏仍为原12项；发票登记的供应商、开票通知、采购合同均出现真实候选（QA261112 测试供应商 / PIN-UIQA-20261117-04-01 / PC-HR36RU）。仓库侧栏仍为“工作台/基础资料/仓库/入仓/…”，入仓供应商与采购合同候选可用，开票通知与打印模板403。[证据](first-batch-reverify-20261118.json)。

## 原修复尝试（已撤回）

- 曾直接授予财务/仓库`perm-supplier-view`等模块查看权限，会导致侧栏新增“供应商资料/采购合同/开票通知”菜单，属于权限范围扩大而非最小选项读取，已撤回并改为上述受限权限。
