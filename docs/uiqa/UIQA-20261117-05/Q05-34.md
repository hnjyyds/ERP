# Q05-34：列表加载失败被显示为“首次建档/暂无数据”空态，且无重试

P2，2026-11-19 登记，**开放**。已实测对象：P02 供应商资料、P03 客户资料、P04 合作伙伴、P05 单证资料、P06 出口报价、P07 出口合同、P08 采购合同。

## 现象

阻断各页列表接口后刷新，页面不显示加载失败，而是进入“首次建档”空态：

- P02：“还没有供应商资料 / 点击“新增供应商”建立第一条资料，之后可在这里搜索和维护 / 去新增供应商”
- P03：“还没有客户资料 / 点击“新增客户”建立第一条资料……”
- P04：“还没有合作伙伴资料 / 点击“新增合作伙伴”建立第一条资料……”
- P05：“暂无数据 / 完成首次录入后，这里会显示对应记录”

P06/P07/P08 同样显示“暂无数据/还没有出口合同/还没有采购合同 + 完成首次录入后，这里会显示对应记录”，并弹出网络异常 toast，列表区无重试。

七页均只弹出“网络连接异常，请检查网络后重试”的 toast，列表区没有重试入口；解除阻断后需整页刷新才恢复。

## 影响

加载失败被表述为“没有数据/尚未建档”，用户可能据此重复建档或误判业务为空；与真实无数据、筛选无结果无法区分。

## 与 Q05-28 的边界

Q05-28 关闭时只在 P01 商品、P09 出货、P24 供应商发票/应付账款四区完成“失败→重试→恢复”复验，未覆盖基础资料 P02–P05。本条不是 Q05-28 的回归，而是当时未覆盖的影响面。

- 共享 `ListEmptyState` 已支持 `error`/`onRetry`；29 个页面文件、32 个页面全部接入独立 `loadError` 与重试回调，多列表页面分别记录、分别重试。
- 部署：`index-nah24HOd.js`，frontend `sha256:2a98504f45b7465453143b6eeb7edd18476174f1082a7a546cd9d1cca6d30a0c`。
- 复验：39 个查询区逐一执行“失败→解除→点击重试→恢复”，均出现“加载失败”而非“首次建档/暂无数据”，点击重试后恢复且未整页刷新；证据 [batch1](q05-34-reverify-20261119-batch1.json)、[batch2](q05-34-reverify-20261119-batch2.json)。

- 未逐区：P32 其余 5 个页签共用同一错误标志与接口，仅当前页签实测；P25 付费申请子表无该空态组件。
