# Q05-26：入库关键词被当成库存查询条件，“可用库存”清零且详情余额为空

级别P2；版本`index-By6s5oGf.js`；admin；`/warehouse/inbound-orders`及详情；1440×900；只读，未生成或审批入库单。

## 实际表现

1. 默认现场：入库单1条（XP-IN-MVU9CU），顶部统计“入库单1 / 草稿0 / 待审批0 / 已审批1 / 可用库存59.00 / 待检库存0.00”；详情库存余额1条59 pcs。
2. 在“入库搜索”输入已有单据号`XP-IN-MVU9CU`后查询：列表正确命中1条，但“可用库存”变为`0.00`，URL为`?q=XP-IN-MVU9CU`。输入部分号`XP-IN`同样为0.00。
3. 同一关键词接口核对：`inventory-balances?q=XP-IN-MVU9CU`返回total 0、available 0；`q=QA261112-P01`返回total 1、available 59.0000；不带q也返回59.0000。说明“可用库存”被列表单据关键词直接过滤。
4. 从已筛选列表（`?status=approved&q=XP-IN-MVU9CU`）点“查看详情”：顶部“可用库存”恢复显示59.00，但“库存余额”区为“暂无库存余额”，库存流水仍有1条。等待10.5秒不变；在详情URL刷新后余额恢复为1条59 pcs。

预期：单据关键词只影响单据列表；“可用库存/待检库存”应保持全库或明确标注筛选范围。详情“库存余额”应按当前单据商品加载，而不是沿用列表关键词。

## 根因

[useInboundOrdersList.ts](file:///Users/dev/Documents/新裴贸易/frontend/src/app/pages/warehouse/hooks/useInboundOrdersList.ts#L151) 把`summaryInventoryQuery`设为`inventorySearch || 列表q`，并在第165行以该值请求`listInventoryBalances`；第182行又把列表`search`作为`loadInventorySnapshotForOrder`的`fallbackSearch`。[useInboundInventory.ts](file:///Users/dev/Documents/新裴贸易/frontend/src/app/pages/warehouse/hooks/useInboundInventory.ts#L27-L33) 的查询优先级为：详情库存搜索 → 列表关键词 → 当前单据首个商品编码，因此从筛选列表进入详情时，余额按单据号查询而空表。

## 建议

统计和详情库存查询不要复用单据列表关键词：统计固定用全库或独立库存条件；详情优先使用当前单据商品编码/明细，仅在用户显式操作“库存搜索”时覆盖。修复后复验：默认、单据号命中、部分号、无匹配、从筛选列表进详情、详情刷新六条路径。

本轮只记录，未修改源码或数据。

## 修复与部署复验（2026-11-18，已关闭）

- “可用库存/待检库存”只按库存搜索框或全库查询，不再复用单据列表关键词。
- 详情库存查询去掉列表关键词回退，优先使用当前单据商品编码；详情刷新不再传列表`search`。
- 测试：`InboundOrdersPage.test.tsx`新增关键词隔离用例，前端410通过。
- 部署复验：默认59.00；`q=XP-IN-MVU9CU`、`q=XP-IN`、`q=ZZZ-NO-MATCH`下可用库存均为59.00；从筛选列表进入详情库存余额1条59 pcs；清空恢复1条59.00。[证据](first-batch-reverify-20261118.json)、[详情](screenshots/P19-firstbatch-detail-from-filter-1440.png)。
