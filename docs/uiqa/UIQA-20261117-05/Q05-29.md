# Q05-29：跨发票选择付款申请时，审批区混用当前发票与所选申请对象

级别P2；版本`index-By6s5oGf.js`；admin；PAGE-24付款管理；1440×900；只读，未提交审批、未付款。

## 实际表现

发票A（`UIQA-20261117-04-INV01`）当前时选择属于发票B的PR-GZN8H6（RMB 60.00）：行选中为PR-GZN8H6，但“审批金额”显示0.00（发票A未付0.00）。

反向在发票B（`QA261112-INV01`）当前时选择属于发票A的PR-PG3X2P（CNY 0.01）：行选中为PR-PG3X2P，但“审批金额”显示0.00（发票B未付0.00），不是该申请的0.01。若先点B的PR-GZN8H6再点A的PR-PG3X2P，审批金额从60.00变为0.00；在A申请已被默认选中时再次点击该行，还曾瞬时显示0.01，说明行点击与发票守卫两条赋值路径不一致。

同时，“新增付款申请”表单的金额与币种取当前发票（B未付0.00、RMB），而申请列表选中行属于另一张发票（A、CNY 0.01），同一屏幕出现两套对象。

接口证据显示两条旧申请的申请、批准、已付金额均为60.00，不是缺少审批金额：[P24-approved-metadata-network.json](P24-approved-metadata-network.json)。

## 根因

[usePaymentsModule.ts](file:///Users/dev/Documents/新裴贸易/frontend/src/app/pages/finance/hooks/usePaymentsModule.ts#L148-L171) 在申请不属于当前发票时把`requestForInvoice`置空，随后：

```ts
approved_amount: requestForInvoice?.requested_amount ?? selectedSupplierInvoice.unpaid_amount
```

审批金额因此回退为当前发票未付金额；同一个effect还把`supplier_invoice_id / requested_amount / currency`重置为当前发票。选中行仍保留跨发票申请，形成“选中A申请、审批B金额”的混用。行点击处理器还会直接写入申请金额，进一步造成瞬时不一致。

## 影响

审批人可能把A发票的0.01申请按B发票的0.00提交，或反向把60.00申请按0.00审批；对象与金额均可能错配。该分支禁止提交审批，本轮未点击审批付款。

## 与Q05-19的边界

- `payment_account`为`null`的两条旧申请，界面空白属正常，不计缺陷。
- 已保存批准日期（11月12日/17日）与备注（“QA261112 并发60测试”/“UIQA…仅此申请”）未回显，仍归Q05-19。
- 本缺陷只处理“当前发票与所选申请对象混用”。

## 建议修复

1. 付款申请列表只展示当前发票的申请，或在发票切换时清空跨发票选中。
2. 审批表单只接受`supplier_invoice_id === 当前发票id`的申请；不匹配时清空选中并禁用审批，禁止回退为当前发票未付金额。
3. 行点击不得绕过同一守卫；移除第二条直接赋值路径。
4. 增加回归：A/B发票互选对方申请、已选跨发票申请后切换发票、审批区金额/币种/日期/备注与选中申请一致。

修复后复验P24发票A/B、三个既有申请、Q05-19历史字段与无跨发票提交。本轮只记录，未改代码或数据。
