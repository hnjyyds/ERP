# Q06-05：按存在的出口合同编号查询不到关联出货单

P2；违反C01；版本 index-AfnHhFyf.js，当前系统管理员/超级管理员，/sales/shipments。

前置：SP-DAEPEG已审批；详情“出货商品明细”“出口合同出货情况”均显示合同EC-F8D7RX。

步骤：清空所有查询→确认列表有SP-DAEPEG→在“出口合同编号”输入EC-F8D7RX→查询。

预期：保留SP-DAEPEG。实际：列表无匹配，汇总变0；清空后恢复。三档视口均复现。没有通过API/内部ID绕过界面查询。

证据：[详情关联](shipment-detail.txt)、[1440](screenshots/shipment-contract-failure-1440.png)、[1280](screenshots/shipment-contract-failure-1280.png)、[390](screenshots/shipment-contract-failure-390.png)。各同名JSON记录实际值、URL与视口。

根因未定位，建议核对该筛选项以业务编号还是内部ID查询的契约；本轮不把推测当作源码结论。

## 修复与复验（2026-11-17）

- 根因：界面“出口合同编号”的值被作为 `contract_id` 传给接口，后端按 `ShipmentLine.contract_id` 精确匹配 UUID，业务编号必然查不到。
- 修复：新增 `GET /sales/shipments?contract_no=` 参数，按 `ShipmentLine.contract_no` 包含匹配；前端改传 `contract_no`，保留旧 `contract_id` 参数兼容。后端补充命中/未命中用例。
- 复验：8080 三档清空后输入 `EC-F8D7RX` 查询，均保留 SP-DAEPEG（1 行）、无空态；证据 [fix-verification.json](fix-verification.json) 与 `screenshots/q06-05-filter-*.png`。
