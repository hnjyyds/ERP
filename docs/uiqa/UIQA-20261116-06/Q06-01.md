# Q06-01：商品无匹配后清空筛选未恢复列表

优先级 P2。当前版本 `index-AfnHhFyf.js`；角色未核实；路由 `/masterdata/products`。三档 CSS 视口1440×900、1280×720、390×844均复现。具体时间见各JSON。

步骤：默认列表5条 → 输入 `UIQA-NOMATCH-20261116` → 点击查询 → 点击空态“清空筛选”。

预期：搜索框清空，恢复5条商品、2条配件及2件有图商品。

实际：输入框清空，统计仍为0，列表改成“还没有商品资料 / 完成首次录入后，这里会显示对应记录”。再次点击查询才恢复5条。清空操作使已有数据被错误呈现为未建档，影响用户判断。

- 对照同视口 `product-list-*`、`product-empty-*` 和再次查询后的 `product-scroll-*`。

根因未定位，本轮未修改代码。建议检查清空时查询参数与加载结果的时序；修复后沿上述路径复验，并按实际共用组件范围单独回归。

## 修复与复验（2026-11-17）

- 根因：`submitSearch` 先 `setSearch('')` 再调用 `loadProducts(undefined, 1)`，未传关键字，而 `loadProducts` 回退读取闭包中的旧 `search`，导致清空后仍按旧关键字查询。
- 修复：`useProductsPage.ts` 的 `submitSearch` 显式传入 `query`（`loadProducts(undefined, 1, undefined, query)`）；新增前端用例覆盖“无匹配→清空→恢复”。
- 复验：8080 部署版 `index-BAg6ml7C.js`，1440/1280/390 三档均为 5→0→5 条，输入框清空、空态消失；证据 [fix-verification.json](fix-verification.json) 与 `screenshots/q06-01-clear-*.png`。
