## Q-01 — 超付金额解释缺失

前置：已有发票 QA261112-INV01，无需新增数据。步骤：打开“付款管理”，对照供应商发票列表和应付账款查询；在1440×900及1280×720重复查看。实际：发票金额 RMB 100.00、已付款 RMB 120.00、应付余额 RMB 0.00、状态“已付清”，没有超付 RMB 20.00 的说明。预期：可以将应付余额按业务口径显示为0，但须同步解释超付或预付款去向。影响：财务可能遗漏多付款项。收款管理已对相似负余额显示“超额分摊”，可作为跨模块一致性参照，不据此推断账务写入错误。

证据：[付款页](screenshots/23-1440-top.png)、[1280复查](screenshots/23-1280-top.png)、[收款参照](screenshots/22-1440-top.png)。建议：明确超付状态/金额及余额定义。未进行任何付款或退款测试。

## Q-03 — QC 手机按钮挤压

步骤：进入 QC 中心，设置390×844，查看“更多筛选/查询/重置/刷新/新增”操作组，再滚至列表。实际：五个按钮同排，“新增 QC 单”按钮外框约59.20×44 CSS px，文字可用宽度不足。预期：主操作文字完整，按可用宽度换行或分组，中心点击区域不被遮挡。影响：主操作识别受损。桌面1440×900与1280×720作为比较，不据桌面布局推断手机通过。

证据：[手机首屏](screenshots/10-390-top.png)、[滚动后](screenshots/10-390-bottom.png)、[DOM测量](10-scan.json)。最终定向复核：[稳定裁切](screenshots/special-11.png)、[点击打开](screenshots/special-12.png)、[精确测量](qc-button-measure.json)。中心点击有效，问题是按钮文字裁切，不能写成按钮无法点击。建议：为主操作保留内容宽度并允许操作组换行。未确认CSS根因。

步骤：在台账所列页面输入安全关键词 `UIQA-NOMATCH-20261116`，点击查询，待结果稳定；清空后再次查询。实际：部分业务页只显示“暂无数据”，没有明确是筛选无匹配；基础资料页则提供“没有匹配的结果”和清空筛选入口。预期：区分无记录、筛选无匹配及加载失败。影响：用户可能误判资料缺失。各页证据分别引用操作索引的 C02 行，不把同一组件名称当作覆盖证明。

建议：统一空态原因与恢复入口；不能把尚未复现的加载失败场景记为同类已确认问题。

## Q-05 — 合同和财务已付口径不清

步骤：打开采购合同 PC-HR36RU 详情，查看“进度概览”；对照付款管理同合同的 QA261112-INV01。实际：合同详情“已付 RMB 0.00、未付 RMB 250.00”，付款页发票已付款 RMB 120.00。预期：同口径同步；若一个按合同支付、另一个按发票支付，应明确说明范围与不纳入原因。影响：采购与财务判断剩余付款义务可能不同。本结论是展示口径缺口，不是后端计算根因认定。

证据：[采购详情完整语义记录](07-action-1.txt)、[采购已付金额截图](screenshots/special-13.png)、[付款页](screenshots/23-1440-top.png)。建议：核对业务定义后统一展示或增加口径说明；禁止为验证再次支付。
