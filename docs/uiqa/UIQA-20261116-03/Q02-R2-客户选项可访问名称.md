# Q02-R2 / P3 — 客户下拉选项的可访问名称仍为UUID

结果：已修复（2026-11-16，提交 `ba79cda`，已推送 origin/main 并部署 8080）。

## 修复结果

根因：RemoteSelect 原先通过 `Select.Option` 子节点渲染自定义内容。rc-select 生成隐藏 ARIA listbox 时无法从 JSX 子节点提取文本，回退使用选项 value，因此无障碍树中的 option 名称为 UUID。

修复方式：RemoteSelect 改用 `options` 属性提供带业务名称的选项数据，再用 `optionRender` 渲染“名称 + 业务编号”的可视双行内容。隐藏 ARIA 选项因而使用业务名称，且不改变可视样式。

复验（8080 部署版，资源 `index-Ceqk43QQ.js`）：展开“客户编号”下拉后，浏览器 Accessibility Tree 中两个 option 名称分别为“演示客户｜海湾家居贸易”“QA261112 测试客户”，不再是 UUID；可视选项仍显示客户名称与业务编号双行，键盘展开与选择正常。

测试门禁：出口合同测试的错误模块 mock 已改为保留真实 `ApiError`（提交 `f536f3c`）。全量 402 个用例通过，未处理错误为 0。

复验边界：本次只读取已测 Accessibility Tree 和 DOM，未运行实际读屏语音；其他角色、写入流程等原有未测项不因此自动通过。

## 环境与复现

2026-11-16，localhost:8080，脚本资源index-DrCylGXT.js，1440×900，ego-lite，当前已有登录会话（角色未独立核定）。

1. 打开出货明细列表。
2. 聚焦“客户编号”下拉，按ArrowDown展开。
3. 查看可视选项，并读取浏览器Accessibility Tree的option名称与对应DOM ARIA属性。
4. 关闭后再次展开，重复读取；结果相同。

## 预期与实际

|可视选项|浏览器option可访问名称|
|---|---|
|演示客户｜海湾家居贸易 / UI261114-C01|a8898417-0e7b-4573-a6c4-8400733e9fcd|
|QA261112 测试客户 / QA261112-C01|9d46eb62-a60a-49c1-92e2-bf4f4240884d|

两个option均为ignored=false，其aria-label、aria-labelledby均为空。预期供辅助技术识别的名称也包含客户名称/业务编号。

影响：依赖辅助技术的用户难以按业务名称辨认候选客户。可视文字和本轮客户筛选数据结果均正常，因此不把本项写成“客户筛选仍失效”。未运行实际读屏语音，结论限定为已测Accessibility Tree和DOM事实。

建议：为选项补充与可视业务名称一致的可访问名称；修复后同时检查选项名称、键盘选择和回填。具体代码根因尚未定位。
