# Q02-R1 / P2 — 客户下钻后的出货页标题错误

结果：已修复（2026-11-16，提交 `d0156ba`，已推送 origin/main）。

## 修复结果

根因有两处：

1. 导航函数把带查询串的完整路径写入 `activePath`，页头标题与侧栏选中态按路径匹配时无法命中，退回“工作台”；刷新时 `activePath` 取自 `pathname`，所以表现正常。
2. 出货列表读取的 URL 参数为 `customer`，老板看板下钻生成的是 `customer_id`，因此客户条件既未回显也未参与查询。

修复方式：

- 导航时仅用 `pathname` 更新 `activePath`，查询串变化通过 URL 查询事件通知页面重新读取。
- 出货列表统一读取/写入 `customer_id`，并兼容旧的 `customer` 参数；提交时清理旧参数。
- 客户筛选由文本输入改为客户资料下拉，回显客户名称而非 UUID。

复验：在 5174 与重建后的 8080 部署版分别执行“老板看板 → 客户行 → 查看出货明细”。页头立即显示“出货明细”，侧栏选中“出货明细”，客户筛选显示“QA261112 测试客户”，请求包含 `customer_id=<id>`，列表返回 1 条匹配出货；刷新后状态保持。客户条件实际进入后端查询。

复验边界：本轮只验证客户下钻；销售员月度下钻的 `sales_user_id`/`period` 参数仍未接入出货列表筛选，未在本次修复范围内，不作为已通过项。

## 环境与前置

2026-11-16，ego-lite，127.0.0.1:5174，1440×900。用户手动登录的当前会话，具体角色未由界面独立核定。使用现有客户“QA261112 测试客户”和出货SP-DAEPEG。运行的是当前Vite工作区，非8080部署构建。

## 实际复现

1. 打开老板看板 `/reporting`。
2. 在客户统计行点击“查看出货明细”。
3. 进入 `/sales/shipments?customer_id=9d46eb62-a60a-49c1-92e2-bf4f4240884d`。
4. 等待页面稳定，出货列表已经显示，页头却是“工作台”，导航未显示对应出货选中项。
5. 刷新同一个URL，页头才恢复“出货明细”。

这条路径执行两次均出现异常，刷新前后URL相同。预期是点击后立即得到正确页面标题及导航状态，无需刷新。影响：用户无法可靠识别当前模块和下钻上下文。

## 附带事实与未验证事项

客户输入框在跳转后及刷新后都为空；URL含customer_id。预期客户范围可识别，需检查筛选参数与回显契约。由于当前出货数据只涉及一个客户，本轮未证明后台实际查询是否忽略了客户条件，不能直接写成“跨客户数据错误”。

建议核对前端导航的pathname/search处理及目标页筛选初始化；这是检查方向，不是已确认根因。
