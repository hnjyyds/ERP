## P2 / Q06-02-R1：选择器可见名称与实际业务回填分离

`RemoteSelect.tsx` 的 `onChange` 在第98行读取 `raw.data`，但本组件的 `options={resolvedOptions}` 直接提供 `{label,value,description}`。antd传给onChange的是此选项本身，不是optionRender使用的包装结构。因此第二回调参数为null。

本轮通过真实antd组件的隔离交互测试复现：渲染候选“供应商验收A”→展开→点击→断言回调。

- 预期：`['supplier-a', {value:'supplier-a', label:'供应商验收A', description:'S-A'}]`
- 实际：`['supplier-a', null]`
- 专项测试退出1，1个断言测试失败。[完整日志](option-contract-test.log) · [用例副本](AcceptanceOption.test.tsx) · [退出记录](option-contract-exit.json)

`PaymentsView.tsx`第324、339、354行分别用`option?.label ?? ''`设置供应商名称、开票通知编号、采购合同号。结合上述实际回调，选择后这些业务字段变为空字符串，尽管Select本身仍能显示选中标签。因此原复验JSON的`selected`名称不能证明业务回填完成。

本结论为**组件交互实证＋调用方代码证据**，不是8080保存链路实测。没有通过React内部状态读写或业务API构造证据。专项用例在frontend测试目录临时运行后删除，只将副本及日志保留在证据目录。

建议：从onChange直接透传选项业务数据，并加入选择A→B→清空及发票名称/编号回填的测试。修复后重跑三个关联选择器及RemoteSelect的已知调用位置；仅改单参数调用的兼容性不能替代这些检查。
